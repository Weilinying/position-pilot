# M9 — 当前持仓层级、批次与录入交互执行计划

日期：2026-09-10
状态：实现与自动验证已完成；等待 Human Acceptance。
所属阶段：M9，沿用 v1.1.0，不新增 M9.1。

本计划承接 [M9 原执行计划](m9-asset-identity-portfolio-import.md)。原 Asset / Recognition 能力保留；本次新增工作的范围、界面和验收以本计划为准。

## 1. 确定的方向

保留 Transaction / Cash Event 历史与确定性重放。持仓主页面展示当前状态与剩余批次，用户无需维护两份“当前 / 起始持仓”。新增买入生成批次，卖出减少指定批次，完全卖出的批次退出当前列表但历史保留。

每批类型允许在 UNSPECIFIED / SWING / LONG_TERM 间调整；分类变化记录生效时间，不产生交易、不改变现金、总股数或总成本，不覆盖过去的交易分类。实际成交字段不可原地覆盖，录错通过引用原交易的更正记录修正并重放。

当前为本地开发测试阶段，不实现旧测试数据回填、历史批次推断或新旧核算双模式。现有本地测试数据库需重建到新 Migration Head 后按新模型重新录入；重置不是卖出，不生成收入，不删除账户或凭据。

## 2. 页面与操作

### 图片与 ticker

- 删除 setup、opening、reconciliation 三处“浏览图片”按钮。保留上传区选择文件、拖放、粘贴与移除。
- 点击上传后的缩略图打开大图；支持键盘打开、Esc 关闭及焦点恢复。查看图片不触发识别或再次上传。
- ticker 输入框直接显示 Provider 返回的联想下拉，取消独立搜索区和搜索按钮。输入 AAO 时展示真实候选，不硬编码示例股票。
- 搜索使用短暂防抖，旧响应不能覆盖新输入；支持方向键、Enter、Esc。复用现有 Asset Binding / Validation，修改文字即清除旧绑定。录入与买卖表单复用同一交互。

### 当前持仓

每个 ticker 默认一行：股票、当前股数、平均成本、未实现盈亏、未实现盈亏百分比、市场价值。点击股票行展开，列保持对齐：

```text
股票总体                     股数 / 均价 / 未实现盈亏 / 盈亏% / 市值
  未分类批次 A               同上 + 购买时间 + 类型选择
  未分类批次 B
  波段仓                     小计
    批次 C
  长期仓                     小计
    批次 D
```

- UNSPECIFIED 批次直接挂在股票下，不显示“未分类仓”标题；其后先波段、再长期。空分组不展示。
- 每组批次按购买时间升序排列，未知时间放在已知时间之后。类型修改后移动到对应层级。
- 主页面移除起始持仓、校准事件的并列记录区；交易历史保留在次级入口。
- 数字列紧凑右对齐，批次通过缩进表达层级；窄屏允许横向滚动。

### 保存后仍可手工修改

- 截图只是生成草稿的一种方式，保存后不需要重新上传即可修改。
- 类型直接在批次行选择。当前剩余股数、均价和盈亏是计算结果，不接受任意覆盖。
- 交易形成的批次提供“更正交易”：带入原成交数量、成交价、时间；保存更正记录并重算现金、批次与汇总。双击相关字段可打开该表单，但不把剩余数量误当原成交数量，也不把含费均价当成交价。
- 仅有截图聚合值的导入记录提供“手工校准”：带入已存值，通过校准记录修正，不改现金、不伪造交易。无需截图创建编辑草稿，source 按实际来源记录。
- 手工校准只编辑 Opening / Reconciliation 形成的单条汇总批次。已有 BUY 购买批次或同一类型包含多个批次时，汇总校准拒绝覆盖，用户改用购买批次更正或交易录入；系统不自动把总量差额分配到各批次。
- 新买入使用“买入”新增批次；批次行“卖出”默认选中该批次并填写实际成交信息。股票级卖出可选多个批次，分配股数之和必须等于卖出数量。
- 编辑 Enter 保存、Esc 取消，失败保留输入；保存成功刷新各层并在重载后保持。保留触屏/键盘等价入口。

## 3. 最小核算语义

### 批次与交易

- BUY 建立稳定批次 ID，关联原交易；剩余股数与原成交股数分别表达。Opening / 校准产生的持仓来源明确，不冒充 BUY。
- 截图没有购买明细时，M9 显示一条“导入持仓·购买时间未知”，不将上传时间当购买时间，也不推测或拆分历史批次。未来若增加显式拆分，必须保持总股数和总成本一致。
- SELL 明确引用扣减批次，不自动猜 FIFO。按所选批次释放成本，剩余加权平均成本可能变化；替代原“部分 SELL 永远保持聚合均价”的规则。
- 类型调整作用于整个批次当前剩余部分；已经卖出的部分及对应历史归属不跟随改写。本次不提供批次内部分转类型，避免为尚未提出的操作增加 Lot Split 关系。
- M9 的购买批次更正保留原 BUY 记录，以 `BuyTransactionCorrection` 引用原交易并按有效成交事实重放；后续卖出与现金约束一并校验。若更正导致超卖或负现金，整次拒绝并说明关联问题，不做自动修复。SELL 更正留到出现明确产品需求时设计。
- 历史交易保留已有 commission / fee schedule。新 BUY 输入券商显示的含费平均成本，`commission=0` 且标记 `BUY_COST_INCLUDED`；新 SELL 接受可选实际 Fee 并标记 `SELL_ACTUAL_FEE`。Transaction Import 保留在 M10。
- Domain 是唯一计算来源，批次、Position、Cash 与 Agent Context 使用同一重放结果；不建立第二份独立可编辑的持仓事实。

### 估值

M9 完成本次表格需要的未实现指标；M11 再增加已实现盈亏并完善真实费用下的核算。

- 市场价值 = 有效行情价格 × 剩余股数。
- 未实现盈亏 = 市场价值 − 剩余成本；盈亏百分比 = 盈亏 / 剩余成本 × 100%。不扣未来卖出费用。
- 类型 / ticker 汇总数量、成本、市值、盈亏；均价和百分比由汇总值重算，不平均子行百分比。使用 Decimal 和既有精度规则。
- 复用 Alpaca Market Data Boundary；同一 ticker 各层共享一次报价。显示价格时间、来源和已有覆盖信息。
- 页面可见时默认每 30 秒刷新，支持手动刷新，隐藏时暂停；实施时用实际标的数量核对现有请求额度。不增加 WebSocket、Cache 或新 Provider。
- 无行情、最后成交超过 7 个自然日或请求失败时保留数量与成本，估值明确不可用；Adapter 与 Portfolio Valuation Service 都按 `last_trade_at` 检查，不把获取时间当成交时间，不将快照轮询表述为逐笔实时。

## 6. Human Acceptance 修复（2026-09-10）

- 用户反馈每 30 秒不能操作：原轮询调用完整 Portfolio Refresh，触发表单禁用及持仓 DOM 重建。改为只请求估值、原位更新数字和报价时间，保留输入、焦点、展开状态；并丢弃跨持仓变更的过期响应。
- 手工编辑只显示 GOOG：原入口只列可聚合校准的导入仓，交易批次被静默过滤。现在同一入口同时显示交易仓及购买更正按钮，沿用已有不可变更正语义。
- ticker 联想最多展示 3 个真实候选；不足 3 个时不补造候选。
- Finnhub `/search` 对短 ticker 前缀可能只返回一个结果，例如 `AAO` 只返回 `AAON`。当前实现仅在短 ticker 形态且普通搜索不足 3 项时读取 Finnhub 实时美国证券目录补齐，不持久化目录；真实验证 `AAO` 返回 `AAOI / AAON / AAOX`。
- 手工编辑不再被问答或识别的全局 busy 状态锁住；点击手工编辑会取消尚未完成的识别，避免旧识别结果覆盖用户输入。保存与重新验证按钮仍在相关请求期间禁用。

- 识图 INVALID_PROVIDER_RESPONSE 尚未复现到同一截图：真实配置的文本识别返回 OK。新增仅含响应形状和固定失败阶段的诊断日志，区分 completion_parse / draft_schema；保持严格字段校验，不添加未经证实的格式容错。需使用原截图再次识别确认根因，当前不标记该反馈已修复。
