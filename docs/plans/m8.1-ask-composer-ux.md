# M8.1 Ask Composer UX 执行计划

## 1. Milestone 目标

M8.1 是 `v1.0.1` Maintenance Release。目标是在不改变 Investment Question API、
Session-derived Identity、Question Failure / Cancellation 和单轮独立问答语义的前提下，
让 Ask Composer 符合常见对话输入习惯：

```text
Enter                  → 提交一次有效问题
Shift + Enter          → 保留换行，不提交
IME composing + Enter  → 只完成候选词，不提交
empty / pending        → 不产生 Request
```

本 Milestone 不新增前端 Framework、自动化 E2E Toolchain、Backend API、Conversation
Memory 或 Idempotency Infrastructure。

## 2. 当前实现与差距

- `frontend/index.html` 已使用 `textarea` 和标准 `form submit`，按钮提交路径完整。
- `frontend/app.js::handleQuestion` 已在同步路径设置 `questionPending`，并负责空问题校验、
  Request Generation、取消、失败展示和按钮禁用。
- 当前没有 Question Textarea 的键盘事件处理；Enter 只会插入换行。
- 现有 `tests/test_product_interface.py` 是静态 Product Interface Contract Test；复杂浏览器
  交互按 ADR 0008 和 M8 已批准边界使用固定 Browser Smoke，不引入 Node / Playwright
  作为新的默认 Regression Gate。

## 3. Acceptance Criteria

1. 非 composing、非 pending 且 Trim 后非空时，Enter 阻止默认换行并通过既有 Form Submit
   路径发送一次 Request。
2. Shift+Enter 保留浏览器默认换行，不触发 Submit。
3. `KeyboardEvent.isComposing`、显式 Composition State 或兼容性 `keyCode === 229` 表示
   IME 仍在 composing 时，不阻止输入法完成候选，也不触发 Submit。
4. Enter 自动重复事件和 pending 期间的 Enter 不产生第二次 Request；pending 期间按钮仍由
   既有 `updateControls()` 禁用。
5. 空白输入的 Enter 和按钮提交都不调用 API，并继续显示既有 `question_required` 错误。
6. 按钮提交、Question Success / Failure / Cancellation、Session Identity 与 Question History
   行为不退化。
7. 相关 Product Interface Test、默认测试与质量检查通过；固定 Browser Smoke 覆盖键盘、
   IME、空输入、pending 和按钮路径。

## 4. 设计决策

### D1 — 键盘事件只负责转交标准 Submit

新增独立 `keydown` Handler，只在满足 Enter 提交条件时调用
`questionForm.requestSubmit()`。实际校验和 Request 仍由 `handleQuestion` 负责，避免形成键盘与
按钮两套提交逻辑，也保留浏览器标准 Form 语义。

### D2 — IME 使用事件事实和本地 Composition State 双重保护

同时使用 `compositionstart` / `compositionend`、`event.isComposing` 和 `keyCode === 229`
兼容保护。IME Enter 不调用 `preventDefault()`，避免干扰候选词确认。

### D3 — 重复提交由输入边界与既有 Request State 共同阻止

键盘层忽略 `event.repeat`，并在 `questionPending` 时阻止 Enter 的默认行为但不 Submit；
`handleQuestion` 继续作为所有入口的最终状态 Gate。M8.1 不增加 Request ID 或后端
Idempotency，因为 Question 是可取消的只读分析请求，当前 Failure Mode 可在浏览器边界解决。

## 5. 执行任务

### T1 — Ask Composer Keyboard Contract

- 在前端 State 中增加短生命周期 Composition 标记。
- 增加 Question Textarea 的 `compositionstart`、`compositionend` 与 `keydown` 绑定。
- 复用 `requestSubmit()` 进入现有 `handleQuestion`。
- 更新中英文 Composer Hint，让用户可以发现 Enter / Shift+Enter 行为。
- 更新静态资源 cache-buster，确保 Maintenance Release 不复用旧脚本。

### T2 — Product Interface Contract Tests

- 扩充 `tests/test_product_interface.py`，锁定键盘绑定、`requestSubmit()`、Shift、IME、
  repeat 和 pending Gate。
- 保留现有安全 DOM、Session Identity 与独立 Question Request Assertions。

### T3 — 文档与边界同步

- 更新 README 的 Decision Questions 说明。
- 更新 `ARCHITECTURE.md` 的 Local Product Interface Boundary，记录 Composer 交互和
  重复提交边界。
- M8.1 不产生新 ADR 或 Engineering Note：它沿用 ADR 0008 的无构建前端与 Browser
  Smoke 决策，没有新的长期架构选择或系统性 Failure Mode。

### T4 — 验证、Automated Review 与修复

- 运行相关 Product Interface Test。
- 运行默认 pytest、Ruff format / lint 与 mypy；外部 Provider / Database Tests 按既有
  opt-in 条件记录 Skip，不能声称未执行的检查通过。
- 使用 Engineering Browser Smoke Fixture 验证：Enter 单次提交、Shift+Enter 换行、
  composing Enter、空输入、`SLOW_A` pending 重复键盘 / 按钮、按钮正常提交和 Failure。
- 由独立 subagent 对已通过基础检查的 diff 做 Automated Review；修复后重跑受影响检查。
